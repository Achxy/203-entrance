# Lighting application protocol 1 (candidate)

All messages below travel inside a Security2 session **after** P-256 transcript
binding. The role is the server's proven credential profile, never a JSON field.
Messages and replies are UTF-8 JSON, at most 1008 bytes; unknown or duplicate
fields fail. Integers used for 64-bit identities/epochs/clocks are decimal
strings, avoiding JSON/JavaScript precision loss. UUIDs are 32 lowercase hex
characters without hyphens. Device boot IDs are 16 lowercase hex characters.

Every request has `v:1` and `op`. Every reply has `v:1`, `ok`, and `code`.
Application rejection is an authenticated reply, not a transport/crypto error.
No operation accepts an IP address, URL, UDP port, arbitrary WiZ method, or raw
bulb JSON. Names are self-asserted labels, not verified human identities.

| Operation | Additional request fields | Behavior |
|---|---|---|
| `guest.enroll` | `token` (64 hex characters generated by client CSPRNG), `name` (1–32 UTF-8 bytes) | Requires current guest SRP profile. Durably creates an individual grant; returns `grant`, `guest_epoch`. Retrying the same token reuses the same active grant. Never automatically invoke after revocation. |
| `guest.resume` | `token` | Binds this transport route to an existing current grant. After a new device boot, fresh current SRP proof plus the retained unrevoked token durably renews the same record slot under a new grant ID. Revoked, old-epoch or same-boot expired grants fail. |
| `room` | none | Returns `boot`, `now_ms`, `policy_epoch`, `guest_epoch`, `last_sequence`, `enabled`, `frozen`, `owner_held`, and storage/driver state. Does not claim a bulb state. |
| `light` | `index` 0–7 | Returns one enrolled light's name/MAC/capabilities/observed values/revision/reachability. No credentials. |
| `sessions` | `page` 0–15 | Owner only; returns one guest label, grant ID and revocation/expiry state. |
| `set` | `id`, `boot`, `policy_epoch`, `sequence`, `expires_ms`, `targets` 1–255, `expected` (8 uint32 values), `patch`, optional `hold_ms` 0–60000 | Absolute intent; accepted/queued receipt only. Every send is reauthorized immediately before UDP. |
| `command` | `id` | Returns correlated receipt: `queued`, `sent`, `verified`, `partial`, `unknown`, `rejected`, `superseded`, or `timed_out`, with target masks. |
| `freeze` | `targets`, `duration_ms` 0–86400000 | Owner only, durable. Zero resumes. A reboot conservatively preserves an active freeze until an owner clears it. |
| `revoke` | `grant` decimal string | Owner only, durable. A session revoke is not a person ban when that person still knows the shared password. |
| `revoke_all` | none | Owner only; increments durable guest epoch and closes guests. |
| `rotate_guest` | `salt` (32 hex characters), `verifier` (768 hex characters) | Owner only; replaces SRP guest verifier and revokes all grants in the same durable record. No retain-existing-session option. |
| `discover` | none | Owner only; read-only probes of associated AP/DHCP peers, one request at a time. Does not factory-reset, move or blink devices. |
| `candidate` | `index` 0–7 | Owner only; returns `discovering`, `count`, `present`, `mac`, `identified`, `module`, `firmware`. Identification is unverified LAN evidence, not bulb signature enforcement. |
| `discovery_cancel` | none | Owner only; stops probing and releases the temporary driver slot. |
| `adopt` | `candidate` 0–7, `name`, `legacy`bool | Owner only; only a gateway-discovered, identity-confirmed AP peer can be adopted. Legacy opt-in acknowledges direct LAN control bypass. |
| `remove` | `index` | Owner only; removes gateway enrollment, not a factory reset. |
| `home_key` | `key` (32 hex characters) | Owner only; imports the WiZ local-integration key, separate from owner/root keys. Does not reset or commission bulbs. |

`patch` supports only implemented fields: `power`bool, `brightness` 1–100,
`rgb`[r,g,b], `kelvin`, `scene`, `speed`. Capability validation occurs before
authority submission. The driver does not silently alter an authorized intent.
Use explicit `power:false`, not brightness 0 or toggles. Group capabilities are
the intersection of members; unsupported/mixed commands are rejected.

Light pages report `legacy_control` from the explicit enrollment policy even
when the gateway signs its own writes. A configured home key does not prove that
a bulb rejects unsigned requests. `permission_enforcement` is `gateway_only`
for legacy opt-in, otherwise `requires_hardware_validation`; neither is a claim
of measured signature enforcement.

The client gets a fresh `room` and the affected `light` records before a write.
It uses gateway monotonic time and a maximum two-second validity interval. The
transport's original boot-bound lease deadline also applies; receiving a late
frame cannot extend command life. Once accepted, poll `command` before promoting
any target to confirmed. Then fetch current `light` records. Lost replies must
reuse the original command UUID; never replay an old intent under a new ID.

## Credential and persistence boundary

For this version, “Remember access on this Mac” retains the guest password plus
the unique grant token in non-synchronizing Data Protection Keychain. The shared
password is needed for fresh SRP after a path change. A grant token alone cannot
reestablish SRP with a shared-password verifier. Revoked grants are never silently
reenrolled. Explicit rejoin with a new token is possible for anyone who still
knows the password; rotate the password to revoke that knowledge.

Core grant deadlines are monotonic and boot-bound. After a restart, a remembered
unrevoked/current-epoch token plus fresh knowledge of the current guest password
can renew its own record under a new monotonic grant ID. The token hash and label
stay in the same slot; no other installation is evicted. This is a 24-hour lifetime
**within a boot**, not an absolute wall-clock expiry across power loss. A revoked
or old-epoch token never renews. An owner revoke using an ID superseded by renewal
returns conflict and requires refreshing the session list; it cannot falsely
claim the newly resumed installation was revoked. The owner key remains valid.

Onboarding uses the documented WiZ app to put bulbs on the gateway AP, followed
by owner discovery/adoption and an explicit physical control check. This service
does not invent a universal consumer pairing protocol. Candidate discovery,
model support, live round-trip control and the native adapter remain separately
qualified integration paths.
